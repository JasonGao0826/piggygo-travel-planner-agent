# 小猪游记上线指南

把网站放到网上，让同行的朋友用手机打开。做法是：代码放在 GitHub，Render 运行网站，再接上自己买的域名。

登录方式是**每人一个专属邀请链接**，点开就是本人身份，不用注册账号。

---

## 0. 先看全貌

### 要注册的账号

| 账号 | 用来做什么 | 需要准备 | 费用 |
|---|---|---|---|
| GitHub | 存放代码，Render 从这里取代码 | 邮箱 | 免费（私有仓库也免费） |
| Render | 运行网站（新加坡机房） | 邮箱或 GitHub 登录、信用卡 | Starter 方案 7 美元/月，硬盘 1GB 约 0.25 美元/月 |
| Cloudflare | 买域名、管理域名解析 | 邮箱、信用卡 | .com 约 10–11 美元/年 |
| OpenAI | 已经有了，上线时把 API key 填到 Render | — | 按用量计费，记得设每月上限 |

每月固定开销约 7.3 美元，另外每年约 11 美元域名费，再加上 OpenAI 的用量。

### 顺序和时间

1. 注册 GitHub，建私有仓库，我把代码推上去（15 分钟）
2. 注册 Render，按 Blueprint 一键部署（20 分钟，其中构建要等 5–10 分钟）
3. 给 OpenAI 设每月上限（5 分钟）
4. 在 Cloudflare 买域名（15 分钟）
5. 把域名接到 Render（15 分钟，证书签发要等几分钟到一小时）
6. 用自己的域名打开管理页面，载入行程，给每人生成邀请链接（5 分钟）
7. 请国内的朋友测试能不能打开

> **安全第一条**：OpenAI 的 API key 只填在 Render 的网页上。不要发在聊天里，不要截图，不要写进任何文件。

## 1. GitHub：放代码

1. 打开 <https://github.com/signup> 注册（邮箱 + 密码，按提示验证邮箱）。
2. 登录后右上角 **＋ → New repository**：
   - Repository name 填 `piggygo`
   - 选 **Private**（私有，只有你能看）
   - 下面的 README、.gitignore、license **都不要勾**
   - 点 **Create repository**
3. 把页面上显示的仓库地址发给我，形如 `https://github.com/你的用户名/piggygo.git`。
4. 我把上线分支合并到 main 后推送。第一次推送时电脑会弹出浏览器窗口让你登录 GitHub 授权，点 **Authorize** 就行（这是 Git 自带的登录助手，密码不经过我）。

不会上传的东西（已经在 `.gitignore` 里排除）：`凭证例子/`、`案例V1-V4/`、根目录的 PDF、`services/api/.env`（里面有 API key）、本地数据库和上传的文件。

## 2. Render：运行网站

### 2.1 注册和绑卡

1. 打开 <https://dashboard.render.com/register>，选 **GitHub** 登录（之后授权仓库更方便）。
2. 工作区方案选 **Hobby**（免费的那档就够，包含 2 个自定义域名）。
3. 右上角头像 → **Billing** → 添加信用卡。网站用的是 Starter 方案，要绑卡才能建。

### 2.2 一键部署（Blueprint）

仓库里的 `render.yaml` 已经写好了全部配置：新加坡机房、Starter 方案、1GB 持久硬盘、登录方式和各种设置。

1. Render 首页 **New → Blueprint**。
2. 第一次会让你连接 GitHub：选 **Only select repositories → piggygo**，确认。
3. 选择 `piggygo` 仓库，Blueprint 名称随便填（例如 `piggygo`），点 **Connect / Apply**。
4. Render 会列出要创建的东西：一个叫 `piggygo` 的 Web Service 和一块叫 `piggygo-data` 的硬盘。
5. 它会要求填 **OPENAI_API_KEY**：把你的 OpenAI key 粘贴进去（只在这里填）。
6. 点 **Apply / Create**。开始构建，第一次大约 5–10 分钟。
7. 进入 `piggygo` 服务，左边 **Logs** 能看到进度。看到 `Ready` 或页面顶部显示 **Live** 就好了。
8. 页面上方有一个 `https://piggygo-xxxx.onrender.com` 的地址。在后面加 `/api/health` 打开，看到 `{"ok":true}` 就说明网站和后端都在正常运行。

> 这个 onrender.com 地址在国内经常打不开，**只用来检查**，不要发给朋友。发给朋友的一律用第 5 步接好的自己的域名。

### 2.3 查看管理口令和内测邀请码

服务左边 **Environment**：

- **ADMIN_TOKEN**：管理页面的口令，Render 随机生成的一长串。点眼睛图标查看。只有你自己知道。
- **BETA_CODE**：别人想**自己新建行程**时要填的内测邀请码（新建行程会调用模型，花钱）。**保留 Render 生成的那一长串，不要改成好记的短词**（短的容易被猜中），复制后私聊发给要用的人。
- **DAILY_LLM_CALLS_PER_TRIP**：每个行程每天最多调用模型多少次，默认 300。问猪猪一次，它查几轮资料就算几次，通常 2–6 次。
- **DAILY_LLM_CALLS_TOTAL**：全站每天最多调用模型多少次，默认 3000（问猪猪、识别凭证、汇总、读攻略、生成行程都算）。到了上限当天大家都暂时用不了，防止费用失控。
- **DAILY_NEW_TRIPS**：全站每天最多新建几个行程，默认 10。
- 这几个数设成 0 就是"今天不允许"（例如想临时停掉所有模型调用）。删掉这个变量才是用默认值。

这些用量记在数据库里，网站重启、重新部署都不会清零，每天（按服务器时间）重新计算。

改完点 **Save Changes**，网站会自动重启（约 1 分钟）。

## 3. OpenAI：设每月上限

1. 打开 <https://platform.openai.com/settings/organization/limits>。
2. 在 **Budget / Usage limits** 里设一个每月上限，内测建议 20–50 美元；也可以设一个提醒金额。
3. 平时在 **Usage** 页面看用了多少。

网站这边也有保护：每个行程、全站每天的模型调用次数都有上限，新建行程要内测邀请码（猜错太多次会暂停 15 分钟），管理功能要口令。

---

## 4. Cloudflare：买域名

推荐 Cloudflare Registrar：按成本价卖，没有首年低价、续费涨价的套路，自带隐私保护，解析也在同一个地方管理。

1. 打开 <https://dash.cloudflare.com/sign-up> 注册，验证邮箱。
2. 左边菜单 **Domain Registration → Register Domains**。
3. 搜你想要的名字，例如 `piggygo.com`、`piggygo.app`、`xiaozhuyouji.com`。
4. 后缀怎么选：
   - **首选 .com**：大家最熟悉，国内访问也没问题。
   - **.app** 也可以（浏览器强制 HTTPS，更安全）。
   - **不要买 .cn**：要实名认证，网站还必须做 ICP 备案，而备案要求服务器在国内，Render 不行。
   - 避开 .xyz、.top 这类便宜冷门后缀：在国内容易被当成垃圾网站拦截。
5. 加入购物车，填联系人信息（英文或拼音即可，默认不公开），用信用卡付款。
6. 买好后在 Cloudflare 首页能看到这个域名，状态是 Active。

## 5. 把域名接到 Render

下面用 `piggygo.com` 举例，换成你买的域名。

### 5.1 在 Render 添加域名

1. Render → `piggygo` 服务 → **Settings → Custom Domains → Add Custom Domain**。
2. 输入 `piggygo.com`（不带 www），保存。Render 一般会提示同时加上 `www.piggygo.com`，也加上。
3. 记下 Render 显示的目标地址，就是你的 `piggygo-xxxx.onrender.com`。

### 5.2 在 Cloudflare 添加解析

Cloudflare → 点你的域名 → 左边 **DNS → Records**：

1. 如果已经有 **AAAA** 记录，删掉（Render 不支持 IPv6，留着会出问题）。
2. **Add record**：
   - Type：`CNAME`
   - Name：`@`（代表根域名 piggygo.com）
   - Target：`piggygo-xxxx.onrender.com`
   - Proxy status：点成**灰色云朵 DNS only**
   - Save
3. 再加一条：
   - Type：`CNAME`
   - Name：`www`
   - Target：同上
   - **DNS only**
   - Save

回到 Render 的 Custom Domains，点 **Verify**。几分钟后状态变成 **Certificate Issued**，就可以用 `https://piggygo.com` 打开了。

为什么要用灰色云朵：

- Render 要直接验证域名、签发 HTTPS 证书。
- Cloudflare 的代理（橙色云朵）在国内经常更慢或者不稳定。

为什么发给大家的链接都用根域名 `piggygo.com`，不用 `www`：Cloudflare 对根域名会直接返回服务器地址，国内手机查询域名时不需要再去查 onrender.com，被干扰的机会更小。

## 6. 第一次使用：载入行程、发邀请链接

> **一定要用自己的域名打开管理页面**。生成的邀请链接用的是你当前打开的网址，用 onrender.com 打开生成的链接，国内朋友可能打不开。

1. 打开 `https://piggygo.com/admin`。
2. 输入 ADMIN_TOKEN，点 **进入**。
3. 点 **载入新西兰演示行程**。
4. 在行程卡片上点 **生成全部邀请链接**。每个成员会出现一个链接和 **复制** 按钮。
5. 先复制**发起人**的链接（演示行程里是 Nina），自己在手机或电脑上打开。打开后就是发起人身份。
6. 其他人的链接分别**私聊**发给本人。不要发到群里：拿到链接的人就能以那个人的身份操作。

以后：

- **换手机或换浏览器**：用自己的链接再打开一次就行，同一个链接可以在多台设备上用。
- **借用别人的手机或电脑打开过**：用完在首页点「在这台设备上退出」。登录 180 天后也会自动失效，要用链接重新打开。
- **在同一台设备上打开了别人的链接**：网页会先问"要切换身份吗？"，只有你就是那个人时才切换。
- **链接丢了、或者怀疑被转发**：发起人在行程的 **大家** 页签里点那个人的 **重新生成**。旧链接立刻失效，用旧链接登录的设备也会退出。然后把新链接私发给本人。
- **链接只在生成时显示一次**：网站只保存链接的"指纹"，看不到原文。忘了就重新生成。
- 别人想**新建自己的行程**：在首页点 **新建行程**，提交时填内测邀请码。建好后，建的人就是发起人，可以在 **大家** 页签给同行的人生成链接。

注意：本地电脑上的数据（测试行程、上传过的凭证、记的账）**不会**自动带到网上。网上是一个全新的数据库。

## 7. 测试国内能不能打开

1. 请一位在国内的朋友，用手机流量和家里 Wi-Fi 各打开一次 `https://piggygo.com`。
2. 也可以用网站测速工具，输入 `piggygo.com`，看全国各地能不能连通：
   - <https://www.itdog.cn/http/>
   - <https://www.boce.com/>
   - <https://www.17ce.com/>
3. 如果大部分地区打不开：
   - 新域名有时要等一两天才稳定，可以先等等。
   - 还是不行就告诉我。备选办法有：换一个域名、开启 Cloudflare 代理、或者换到香港或新加坡的云服务器。
   - 开启 Cloudflare 代理后，网站看到的来源地址会变成 Cloudflare 的，内测邀请码的试错限制要改成按 `CF-Connecting-IP` 认人，开之前告诉我。
   - 如果以后开启了 Cloudflare 代理（橙色云朵），一定要在 Cloudflare 的 **Caching → Cache Rules** 里加一条：网址路径以 `/api/` 开头的**不缓存**（Bypass cache）。否则行程报告、凭证这些只给成员看的文件可能被缓存，给不相关的人看到。网站自己也会告诉缓存"不要存"，这条规则是再加一层保险。

## 8. 以后怎么更新

- **代码更新**：我改完代码、你同意合并到 main 之后，我推送到 GitHub，Render 会自动重新部署（5–10 分钟）。部署时网站会有一两分钟打不开（因为挂了硬盘，不能无缝切换），尽量避开大家正在用的时候。
- **数据安全**：数据库、凭证文件都在 Render 的硬盘 `/data` 上，重新部署不会丢。Render 每天自动给硬盘拍快照，保留 7 天。需要恢复时在服务的 **Disks** 页面操作。
- **改设置**：Render → **Environment** → 修改 → **Save Changes**，自动重启。
- **硬盘不够**：Render → **Disks** 把 1GB 调大（只能调大，不能调小）。
- **内存不够**：Logs 里出现 out of memory、服务反复重启时，把方案从 Starter 升级到 Standard（2GB 内存，25 美元/月）。目前本地实测前后端加起来约 250MB，Starter 的 512MB 够用。

## 9. 遇到问题

- 网站打不开：先打开 `https://piggygo.com/api/health`，看到 `{"ok":true}` 说明服务本身正常，问题多半在网络或域名解析。
- 功能报错：Render → **Logs**，把出错前后的几十行复制给我（复制前确认里面没有 API key）。
- 朋友说链接"无效或已经作废"：发起人在 **大家** 页签给 TA 重新生成。
- 提示"今天找猪猪的次数用完了"：这个行程（或全站）当天的模型调用次数到上限了，第二天自动恢复；需要的话在 Environment 里把 `DAILY_LLM_CALLS_PER_TRIP` 或 `DAILY_LLM_CALLS_TOTAL` 调大。
- 提示"凭证夹满了"：每个行程最多 80 个文件、150MB，删掉不需要的凭证就行。
- 提示"网站的存储空间快满了"：全站凭证加起来到了 600MB（这是代码里的上限，要调大请告诉我），或者硬盘剩不到 150MB（这种情况在 Render 的 **Disks** 把硬盘调大就行）。也可以删掉旧行程的凭证。
- 提示"内测邀请码试错次数太多了"：同一个网络 15 分钟内猜错 10 次会暂停 15 分钟，一般只影响猜错的那个网络；全站 15 分钟内猜错超过 300 次时，大家都会暂时不能新建行程。

## 附：技术说明（给开发者）

- `Dockerfile`：先构建 Next.js 独立服务器，再放进 Python 3.11 运行环境。容器里跑两个程序：Next.js 对外（`$PORT`），FastAPI 只听 `127.0.0.1:8765`。网页的 `/api/*` 由 Next.js 转给后端，所以网页和后端是同一个网址，登录 cookie（`pg_session`，HttpOnly、SameSite=Lax、上线时带 Secure）能正常带上，也不用处理跨域。
- `scripts/docker-start.sh`：先启动后端、等它就绪，再启动网页；任何一个退出，容器就退出，Render 会自动重启。后端只能开一个进程（生成中的任务、内测邀请码的试错计数记在进程里；每日额度在数据库里）。
- `render.yaml`：Blueprint 配置。`OPENAI_API_KEY` 是 `sync: false`，只在 Render 网页上填；`ADMIN_TOKEN`、`BETA_CODE` 由 Render 随机生成。
- `services/api/requirements.txt`：上线用的固定版本，和本地测试过的一致。
- 登录的实现见 `services/api/tripagent/auth.py`（邀请链接、会话）和 `services/api/tripagent/api/security.py`（检查是否加入行程、把请求里的 member_id 换成登录身份、每日额度）；设计见《设计规格》13.2 节。
- 本地按上线方式试运行（在 Git Bash 里；PowerShell 设不了空字符串的环境变量）：
  1. 后端：在 `services/api` 下，`AUTH_MODE=invite DATA_DIR=<一个空目录> ADMIN_TOKEN=<随便> BETA_CODE=<随便> .venv/Scripts/python.exe -m uvicorn tripagent.api.main:app --port 8766`。登录 cookie 默认只走 HTTPS，但浏览器把 localhost 当作安全的，本地 http 也能用。
  2. 网页：在 `apps/web` 下，`NEXT_PUBLIC_API_BASE= BACKEND_URL=http://127.0.0.1:8766 NEXT_OUTPUT=standalone NEXT_DIST_DIR=.next-prod npx next build`（`NEXT_PUBLIC_API_BASE` 要设成空字符串；构建会往 tsconfig.json 里加一行，用 `git checkout -- tsconfig.json` 改回去）。
  3. 独立服务器不会自带静态文件：`cp -r .next-prod/static .next-prod/standalone/.next-prod/ && cp -r public .next-prod/standalone/`。
  4. `HOSTNAME=127.0.0.1 PORT=3100 node .next-prod/standalone/server.js`，然后打开 http://localhost:3100/admin。
- 安全相关的限制（都在代码里，有测试）：请求体大小按接口分别限制；只认标准表单类型，其他请求体一律按 JSON 检查并换成登录身份；凭证只收图片、PDF、确认邮件（按文件内容判断），只有图片和 PDF 能在浏览器里直接打开；每个行程凭证夹 80 个文件、150MB；成员写的偏好、投票有长度上限，给模型看时标明"只当数据"；猪猪回复里的图片不加载；替别人记的账要付款人确认；体重相关的提醒只给本人看详情；每次登录都换新的会话，会话 180 天过期；接口响应不缓存；网页带内容安全策略，不能被别的网站嵌入。
